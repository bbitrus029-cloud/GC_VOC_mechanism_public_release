# Reproducibility

## Scope actually checked

The release delivers the seven maintained analysis modules and source-specific preparation functions. The four core bulk estimates were recalculated from public patient scores. Deterministic original evidence integration was reconstructed from bundled complete results. Existing numerical and reader/preparation tests used synthetic fixtures. Both plotting modes read saved permitted tables. Other study models, raw inputs, expression scores, annotation graphs and raw-accession preparation were **not** rerun. No new environment was installed or validated.

`./verify` checks the complete physical manifest, independent regular files, 146 original plus 42 supplementary hypotheses, all 41 families, source navigation and required withdrawals. `PUBLIC_MANIFEST.tsv` includes its own size and uses `SELF_HASH_EXCLUDED` for its own digest; every other file has a full SHA-256. Python 3 standard library suffices. Verification writes only stdout/stderr.

## Runtime and runnable commands

Use an existing R 4.6.1 installation. Set `GCVOC_RSCRIPT` to its Rscript executable, `GCVOC_R_LIBRARY` to the selected existing package library (default `NULL`), and optionally `GCVOC_TMPDIR` to an existing scratch directory. The launcher runs `Rscript --vanilla`, UTC and one BLAS/OpenMP/RcppParallel thread. It never installs packages. [Original](workflow/environment/original_packages.tsv), [A/CD supplementary](workflow/environment/supplementary_packages.tsv) and [B epithelial](workflow/environment/epithelial_packages.tsv) package profiles record the actually qualified versions without installation prefixes. Profile matching is checked by reconstruction interfaces. They are version specifications, not a tested clean-environment installation recipe.

Run from the release root. Every output directory must be outside the release, absent or demonstrably empty, readable and searchable; final symlinks, hidden contents and non-listable directories are rejected before writes. Relative paths are resolved through real existing parents. Use different destinations for each command.

```sh
./verify
workflow/environment/run-r workflow/pipelines/check_methods.R
workflow/environment/run-r workflow/pipelines/check_reconstruction.R "$SYNTHETIC_OUTPUT"
workflow/environment/run-r workflow/pipelines/reproduce_core_bulk.R "$CORE_OUTPUT"
workflow/environment/run-r workflow/pipelines/render.R tissue_context "$TISSUE_OUTPUT"
workflow/environment/run-r workflow/pipelines/render.R protein "$PROTEIN_OUTPUT"
```

`check_methods.R` uses the original/base profile and the existing Student-t/metafor SMCRP anchor. `check_reconstruction.R` uses the epithelial profile, imports seven module factories, and tests synthetic abundance parsing, raw-UMI identity guards, protein pairing, archive safety, feature mapping, UMI/QC boundaries, unmatched detection units, panel ties, typed tables and frozen randomization. Fixtures are synthetic, not study records. The same command also exercises input-authority shadow rejection, an artificial four-gene/130-column PDC report, logical-prefix protein preparation, and generated-output dependency containment; synthetic protein preparation intentionally stops at the unchanged study-size check without fitting a model. Rendering uses base graphics/Cairo and saved values, yielding two tissue-context PDF/PNG pairs and one protein PDF/PNG pair without refitting. Font/library differences can affect bytes. The retained non-listable-output regression was tested as an ordinary Linux user.

## Four prespecified bulk estimates

Input: [patient_score_deltas.tsv](results/original/bulk/patient_score_deltas.tsv). Only these exact combinations are selected; repeated sensitivity records are never pooled:

| source | analysis_id | pairs | frozen BH family |
|---|---|---:|---|
| GSE29272 | GSE29272_G | 112 | BULK_CORE_GSE29272 |
| GSE29272 | GSE29272_H | 112 | BULK_CORE_GSE29272 |
| GSE27342_64 | GSE27342_primary_G | 49 | BULK_CORE_GSE27342_64 |
| GSE27342_64 | GSE27342_primary_H | 49 | BULK_CORE_GSE27342_64 |

The command reads only the public manifest, score table, cohort pairing ledgers and frozen crosswalk/configuration. It verifies unique patients, identical G/H patient sets per cohort, complete eligible Tumor/NAT pairs and `delta = Tumor_score - NAT_score` at saved precision. `64` is historical; the overlapping 60-pair population is separate. Accepted `s01_paired_delta_t(Tumor,NAT,patient_ids)` supplies the native mean difference, Student-t interval, statistic, standard error, df and raw P. `s01_paired_g_av` uses both paired vectors, their variances and correlation: standardizer `sqrt((sT^2+sN^2)/2)`, df correction `2(n-1)/(1+r^2)`, gamma bias correction and the retained sampling-variance/normal-interval formula. BH is applied separately to each original two-member G/H family. Output: `core_bulk_estimates.tsv` and `input_checks.tsv`, with stable endpoint/hypothesis IDs, biological n, result states and 17-digit output.

Calculation was saved before the accepted estimates were read. The comparison rule was declared first: exact identities and missingness; `abs(calculated-reference) <= 1e-13 * max(1,abs(reference))`, the existing original-bulk rule. Additionally positive P/q must remain positive with relative error at most `1e-10`; zero cannot pass as a tiny positive value. All four rows passed against [all_program_estimates.tsv](results/original/bulk/all_program_estimates.tsv) and frozen family records. Maximum absolute difference was `4.263256414560601e-14`; maximum P/q relative difference was `4.707345624410664e-14`. A deliberately zeroed reference P was detected. Newly reported calculated SE/df/g variance are distinguished from historically unavailable fields; no unavailable reference statistic was fabricated.

## Explicit reconstruction interfaces

All analysis functions are under [workflow/R/analysis](workflow/R/analysis). `source('workflow/R/common/load_analysis.R'); load_public_analysis()` loads definitions without running analysis. `public_analysis_context(scope, manifest_path, output_root)` binds inputs and safe outputs. `public_preparation_context(ctx)` adds source-specific configuration. The seven factories expose their maintained functions and `run()`; formulas, seeds, populations and terminal states are retained. Private approval/orchestration records are replaced by explicit current input hashes, not simulated historical approvals.

[reconstruction_inputs.tsv](workflow/config/reconstruction_inputs.tsv) gives each module's logical input keys, bundled paths where available, schemas and recorded source identities. Its `binding_rule` distinguishes `BUNDLED_MANIFEST`, `EXACT_ACQUISITION` and `RECONSTRUCTED_INTERMEDIATE`; `authority_sha256` is mandatory for catalogued exact acquisitions and is not inferred from a historical RDS hash. [bundled_input_aliases.tsv](workflow/config/bundled_input_aliases.tsv) maps legacy relative keys to permitted canonical public files. Keys beginning `data/processed/`, `data/manifests/` or `reports/qc/` identify dependencies; they are not filesystem fallback routes. The new interface resolves only those aliases, manifest-listed public files and explicitly declared local inputs.

Copy the header-only [input manifest template](workflow/config/reconstruction_manifest_template.tsv) outside the release. Add one row per externally supplied object with exactly `logical_input`, `local_path`, `sha256`; local paths may be absolute or relative to that manifest. Hash actual files with SHA-256. Do not populate the manifest by copying excluded private objects. Bundled files, including program definitions, crosswalks, seeds and the governing input/alias catalogs, always use their public manifest identities. A reader mapping cannot shadow a canonical path, logical alias or alternate spelling. The resolver verifies the governing catalogs before using their contents. The distributed public manifest is the trust anchor; retain its recorded release digest and run `./verify`.

For `EXACT_ACQUISITION`, the actual bytes must match both the reader's declared hash and the independently recorded authoritative hash. All four exact molecular acquisitions in [external_input_identities.tsv](workflow/config/external_input_identities.tsv) are enforced by their known object basename, independent of the caller's logical source prefix or physical filename. In particular, C/D checks PDC000214 SHA-256 `db3c95cde62c7cac0194534810cfc29ef2a4fbb09c25fae8b587bcda174abc25` before its protein report is opened. A self-consistent new hash or matching column schema is insufficient.

For `RECONSTRUCTED_INTERMEDIATE`, the explicit reader digest establishes current-file integrity. Historical hashes identify accepted serialized objects but are not mandatory acquisition hashes: new operational metadata or equivalent serialization may change bytes. The maintained scientific checks on identities, ordering, populations, members, backgrounds, values and terminal states still apply; compare complete scientific outputs before claiming equivalence. Identity-only protein preparation tables also use this rule, with authoritative identifier/corroboration checks retained. A new digest alone does not prove scientific equivalence. Missing, shadowed or mismatched inputs fail without acquisition or private fallback.

Generated dependencies are readable only after this context's atomic writer has validated, persisted and registered them. A reserved output name is not a completed artifact. Reads reject traversal, symlinks, unregistered files and modified generated bytes; the canonical target must stay inside the declared output root. External dependencies, including A score/diagnostic objects used by C/D, must instead be explicitly declared outside that root. Prior-run outputs are external inputs, not automatically trusted artifacts of the current run.

```sh
workflow/environment/run-r workflow/pipelines/rebuild_original.R bulk "$INPUT_MANIFEST" "$OUT_BULK"
workflow/environment/run-r workflow/pipelines/rebuild_original.R single_cell "$INPUT_MANIFEST" "$OUT_SC"
workflow/environment/run-r workflow/pipelines/rebuild_original.R protein "$INPUT_MANIFEST" "$OUT_PROTEIN"
workflow/environment/run-r workflow/pipelines/rebuild_original.R integration "$INPUT_MANIFEST" "$OUT_INTEGRATION"
workflow/environment/run-r workflow/pipelines/rebuild_supplementary.R A "$INPUT_MANIFEST" "$OUT_A"
workflow/environment/run-r workflow/pipelines/rebuild_supplementary.R B "$INPUT_MANIFEST" "$OUT_B"
workflow/environment/run-r workflow/pipelines/rebuild_supplementary.R CD "$INPUT_MANIFEST" "$OUT_CD" "$A_PROCESSED_DIRECTORY"
```

A header-only manifest is sufficient for integration because its complete numerical inputs are bundled. Other commands require independently acquired/prepared objects. CD requires both A `rank_scores.rds` and `diagnostic_scores.tsv` in the supplied A processed directory; include their absolute paths as manifest keys as well as the CD keys. Its A dependency is scientifically necessary, not an optional shortcut. Outputs go into `results/`, `processed/` and `qc/` under the declared destination; they are reader reconstructions, not original freeze/acceptance records. Missing-input and output-path checks were exercised for all seven CLI branches; successful imports are not data-based validation of the six external-input branches.
